前端 API 使用文档
一、概述
本项目提供以下核心接口：

聊天接口：接收用户消息，触发行为记录、画像更新、路径规划、资源生成，并返回最新画像、路径和推荐资源。

学习路径接口：直接返回用户当前的学习路径（供前端可视化）。

资源生成接口：根据主题和资源类型（代码/练习/讲解）生成单个资源。

资源浏览完成接口：上报用户浏览资源的时长，用于行为分析和画像更新,推荐资源更新。

题目作答接口：上报用户练习的正确率和耗时，用于分析弱项和调整推荐，行为分析和画像更新，推荐资源更新。

工作流程（状态循环）：

前端维护一个系统状态（例如 profile, path, recommendedResources）。

用户通过交互（发消息、点击资源、完成题目等）调用对应 API。

后端处理请求，更新用户画像、路径规划等，并返回新的状态数据。

前端接收返回数据后，更新本地的系统状态，并重新渲染 UI。

用户继续操作，重复步骤 2–4。

注意：部分接口（如资源浏览完成、题目作答）仅上报数据，后端不会返回新的推荐资源；聊天接口才会返回完整的资源推荐。因此建议：

用户发消息后，用返回的 resources 更新推荐区。

用户点击学习路径时，单独调用 /api/path/{user_id} 获取路径数据。

用户点击生成单个资源时，用返回的资源直接展示，并自行决定是否加入本地推荐列表。

二、接口详情
1. 聊天接口
作用：用户发送自然语言消息（如“我不会页表”），后端进行行为记录、画像更新、路径规划、资源生成，并返回最新数据。

URL：POST /api/chat/

请求体（JSON）：

json
{
  "user_id": "string",
  "message": "string"
}
返回示例：

json
{
  "state": "success",
  "result": {
    "profile": { ... },   // 用户画像（更新后）
    "path": [ ... ],      // 学习路径（更新后）
    "resources": [ ... ]  // 推荐资源列表
  }
}
前端处理：将 result 中的 profile, path, resources 保存到前端状态结构，并更新 UI（例如展示推荐资源卡片、刷新路径图）。

2. 学习路径接口
作用：直接获取用户当前的学习路径（不触发其他更新），用于前端可视化展示（如思维导图、步骤条）。

URL：GET /api/path/{user_id}

路径参数：user_id – 用户唯一标识

返回示例：

json
{
  "status": "success",
  "result": [ ... ]   // 路径节点列表
}
前端处理：调用后更新全局状态中的 path，并重新渲染路径组件。

3. 资源生成接口
作用：用户主动点击生成某一类型的资源（代码案例、练习题、讲解等），后端生成并返回该资源内容。

URL：POST /api/resource/generate

请求体：

json
{
  "user_id": "string",
  "topic": "string",       // 例如 "页表"
  "resource_type": "string"  // 可选 "code" / "exercise" / "explain"
}
返回示例：

json
{
  "status": "success",
  "result": {
    "resource_id": "xxx",
    "type": "code",
    "content": "...",
    "title": "页表代码示例"
  }
}
前端处理：直接展示返回的资源内容。可以将其加入本地的“已生成资源”列表，但不强制要求更新全局推荐区。

4. 资源浏览完成接口
作用：用户关闭或离开资源页面时，上报浏览时长（秒）。后端用于行为分析和画像更新。

URL：POST /api/resource/finish_view

请求体：

json
{
  "user_id": "string",
  "resource_id": "string",
  "duration": 120   // 整数，单位秒
}
返回示例：

json
{
  "status": "success",
  "data": { ... }   // 后端可能返回一些确认信息，前端一般无需处理
}
前端处理：仅上报，不更新状态。注意：前端需自己记录打开资源的时间，离开时计算差值并调用此接口。

5. 题目作答接口
作用：用户提交练习后，上报正确率和耗时。后端用于分析错题、更新弱项、调整推荐。

URL：POST /api/resource/submit_answer

请求体：

json
{
  "user_id": "string",
  "topic": "string",        // 题目所属主题，如 "页表"
  "correct_rate": 0.75,     // 浮点数，0~1 之间的正确率
  "duration": 180           // 做题耗时（秒）
}
返回示例：

json
{
  "status": "success",
  "data": { ... }   // 通常为空或确认信息
}
前端处理：上报后，可主动调用聊天接口或路径接口刷新推荐；或者等待用户下一次主动操作时更新。
